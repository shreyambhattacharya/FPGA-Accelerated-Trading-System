# Historical replay and paper backtesting

This repository now contains a deterministic, offline historical replay and
paper-accounting framework. It is research infrastructure, not a live trading
system and not a profitability claim.

## Architecture

```text
historical dataset
  -> provider/parser adapter
  -> NormalizedEvent (canonical quote/trade)
  -> global chronological merge and session filter
  -> existing MarketModel (exact integer features)
  -> existing StrategyModel (exact candidate semantics)
  -> CandidateSignal telemetry
  -> ExecutionSimulator (hypothetical fills)
  -> PortfolioSimulator (positions, cash, trades, equity)
  -> metrics, forward returns, and reproducible reports
```

The reference models are reused rather than reimplemented. Prices stay in
integer micro-dollars, feature validity and sequence checks remain the same,
and candidate actions/reason bits/scores are the same values used by the FPGA
reference differential tests. The execution and portfolio layers begin only
after candidate generation and never alter the FPGA strategy calculation.

Run a replay with:

```powershell
python -m tools.backtest.run_backtest `
  --data tools/backtest/fixtures/hand_check.csv `
  --config configs/backtest/base.json `
  --output build/backtest_run
```

Use `--quality-only` to validate a dataset without replaying it. Use `--plot`
only when matplotlib is installed; PNG chart generation is optional and does
not add seaborn or a plotting dependency to the core path.

## Execution and position rules

The execution simulator models the first eligible quote at or after
`order_timestamp + latency`. Supported latency examples include 0, 1, 5, 10,
25, 50, and 100 ms. It never fills from a midpoint or OHLCV value:

| transition | executable side |
|---|---|
| long entry | ask |
| long exit | bid |
| short entry | bid |
| short exit | ask |

Fixed micro-dollar slippage, basis-point slippage, per-trade commission,
per-share commission, and minimum commission are configurable. Quote size must
be positive for a fill. A zero-latency order generated by a quote can use that
updated quote; an order generated by a trade waits for the next eligible quote.
Orders that never see an eligible executable quote are reported as unfilled.

The portfolio has explicit flat/long/short state, one position per symbol by
default, no pyramiding, no leverage, fixed-share/fixed-notional/cash-percent
sizing, capacity limits, and optional short enablement. An opposite candidate
closes the existing position by default. Same-event reversal is disabled by
default and can be explicitly enabled. Stop loss, take profit, maximum hold,
opposite-candidate exit, and end-of-day flatten policies are represented in
the configuration. Stop/target triggers use the executable exit side; a gap
is filled at the first eligible quote, not at the threshold.

Cash, entry/exit commissions, gross and net P&L, holding duration, turnover,
exposure, realized/unrealized P&L, and mark-to-market equity are recorded.
Short entry collateral is modeled conservatively against available cash; no
borrow, margin, broker, or order-routing behavior is implied.

## Outputs and research analysis

Each run writes `config.json`, `summary.json`, `quality.json`,
`forward_summary.json`, `report.md`, and CSVs for trades, every candidate,
equity, drawdown, daily P&L, and forward returns. Metadata records the input
path, SHA-256, git commit, provider label, and the fact that this repository
did not download real data for the run.

Metrics include trade counts by direction, win/loss statistics, average and
extreme trade P&L, profit factor, expectancy, average hold, turnover,
drawdown/duration, exposure, concurrent positions, daily P&L, and P&L by
symbol. Sharpe, Sortino, and Calmar are withheld with an explicit warning for
short samples; they are not manufactured from sparse intraday observations.

Forward returns are measured from the candidate timestamp at 100 ms, 500 ms,
1 s, 5 s, 15 s, 30 s, 60 s, and 5 minutes. Long returns use current ask to
future bid; short returns use current bid to future ask. The analyzer selects
the first future quote at or after the horizon and reports distributions by
direction, symbol, score, and reason bits. Score calibration and factor
ablation helpers are in `experiments.py`; ablation policies are software
research variants and are not presented as FPGA behavior.

Parameter grids are bounded, ranked on chronological validation data, and
never use the test segment for selection. Date-based train/validation/test
splits and walk-forward windows are provided, along with no-trade,
momentum-only, VWAP-only, and seeded random baselines. Sensitivity and symbol
split robustness should be reported alongside any selected configuration.

## Reproducibility and limitations

Runs are deterministic for the same canonical bytes, config, sequence policy,
and code commit. Provider downloads, credentials, live feeds, broker orders,
and physical Raspberry Pi/Tang Nano tests are outside this milestone. The
hand-check fixture is intentionally tiny and is useful for accounting and
ordering tests, not for statistical conclusions. Historical Level-1 data can
contain stale quotes, crossed quotes, gaps, venue changes, and missing depth;
the report exposes those limitations instead of hiding them.
